## 3. Top Findings (with confidence + effect sizes)

**F1. Models default to answering, not clarifying — the sanitizer corrects a real default failure. (CONFIRMED existence, extractor full-verified today)**
CLAM (http://arxiv.org/abs/2212.07769v2): "current language models rarely ask users to clarify ambiguous questions and instead provide incorrect answers"; pipeline = detect ambiguity → generate clarifying question → answer after clarification, with simulated users holding privileged information; "significantly improves accuracy on mixed ambiguous and unambiguous questions." This is the sanitizer's charter evidence: without an explicit clarify-vs-absorb step, the agent misunderstands exactly as T-009 feared. The simulated-user method is the ready-made sanitizer test harness (seed conflated intents, privileged-information roleplay, measure downstream revision rate).

**F2. A clarification dataset + pipeline with baselines exists and is directly reusable. (CONFIRMED dataset fact, extractor full-verified today; numbers LIKELY)**
CAMBIGNQ (http://arxiv.org/abs/2305.13808v2): 5,654 ambiguous questions each with passages, possible answers, and a clarification question (InstructGPT-generated, manually revised); pipeline + metrics defined; baselines 61.3 F1 ambiguity detection / 40.5 F1 clarification-based QA. Honest calibration for any sanitizer flag: detection F1 ~60 is the state of the art to beat-or-match, not 90+; design the sanitizer for recall-then-human-discard, never for precision-oracle pretence. Numbers stay LIKELY (single study) and out of design rationale per §5 N4.

**F3. Intent classification and ambiguity resolution belong in one framework — with a cost-viable small-model path. (LIKELY existence; UNVERIFIED numbers — probe failed hard)**
A domain-agnostic framework equips lightweight open-source LLMs to do intent classification *alongside* clarifying-question generation, with a joint evaluation of classification accuracy + clarification timing/quality; instruction-tuned small models match proprietary LLMs at ~8× lower inference cost, and enterprise deployment cut misrouting 8% (https://doi.org/10.48448/c1s5-wj84 — extraction failed, snippet-only → all numbers UNVERIFIED). ★ Complement: CLEAR-KGQA separates *entity* ambiguity from *intent* ambiguity with Bayesian uncertainty guiding when/how to clarify, validated on WebQSP/CWQ with a two-agent user-simulator loop (https://doi.org/10.1109/ijcnn64981.2025.11229206, snippet; also http://arxiv.org/abs/2504.09665, snippet). Design transfer: the sanitizer's three heuristics map exactly onto this split — (H1) split check = multi-intent detection, (H2) XY-probe = latent-intent inference, (H3) clarify-vs-absorb = Bayesian-timing decision.

**F4. Requirements-smell detection gives the sanitizer its flag vocabulary — and pronouns outrank passive voice. (LIKELY, convergent snippets)**
The nocuous-ambiguity programme (https://ieeexplore.ieee.org/document/1704049/; anaphora extension http://ieeexplore.ieee.org/document/5636921/) plus cross-domain ambiguity detection (http://link.springer.com/10.1007/s10515-019-00261-7) plus deep-learning requirements-smell work (http://arxiv.org/abs/2108.03087v1) plus an NLP quality-assessment approach scoring vague terms / incomplete conditions / passive constructions / uncertain quantifiers / weak modals / semantic inconsistency (https://doi.org/10.64035/car.01.2026.28) converge on one point: linguistic-feature flagging works but needs the nocuous/anodyne cut or it over-flags. ★ The Bayesian causal experiment is the sharpest prioritiser: passive voice has only minor impact on downstream domain models while ambiguous pronouns strongly corrupt associations (https://doi.org/10.1007/s10664-024-10582-1, snippet). Sanitizer consequence: weight H1 split-signals (pronoun/conflated-subject flags) above style flags (passive voice); never block a run on style alone.

**F5. Clarification questions can be generated at useful quality — contracts prove the hard case. (LIKELY, extractor full-verified today)**
ConRAP (http://arxiv.org/abs/2403.08053): retrieval-augmented prompting over CUAD contracts detects ambiguities at F2 0.87 with 70% of generated clarification questions judged useful by humans. ★ Complement: the global-vs-local clarification model — identify what is missing by differencing global and local views, then ask about what is useful (http://arxiv.org/abs/2104.06828v1, snippet). Transfer: the sanitizer's clarify output should follow the ConRAP shape (flag + targeted question naming the missing slot), and the H2 XY-probe should use the global-difference trick (what does this request lack that sibling requests carry?).

**F6. Humans clarify task uncertainty, not referential ambiguity — LLMs do the reverse. (LIKELY, single-study snippet)**
Minecraft-dialogue study (http://arxiv.org/abs/2507.10445v1): only a weak link between ambiguity and humans producing clarification questions; humans rarely clarify referential ambiguity but often clarify task-based uncertainty, while LLMs over-produce referential-clarification questions and under-ask on task uncertainty; reasoning increases question frequency and relevancy. Sanitizer consequence, stated bluntly: a sanitizer tuned on referential-ambiguity benchmarks will annoy the user with pronoun questions while sailing past the conflated-goal cases T-009 actually cares about. Tune H1/H2 recall toward *task/goal* splits ("are these two deliverables or one?"), not pronoun splits — pronouns already belong to T-037.

**F7. The XY structure is practitioner-confirmed but study-unmeasured — the sanitizer's H2 rests on the thinnest evidence. (UNVERIFIED — itself a finding)**
The `general`-category pass returned only the practitioner canon (https://www.xy-problem.com/, https://en.wikipedia.org/wiki/XY_problem, https://meta.stackexchange.com/questions/66377/what-is-the-xy-problem, https://xyproblem.info/) — consistent definitions, zero controlled effect sizes. No retrieved study measures XY frequency, detection accuracy, or the cost of asking "what is the actual problem?" In house terms this is a G-gap, not a finding: H2 (XY-probe) ships as a heuristic with UNVERIFIED calibration, gated behind the stakes test, never as a blocking gate.

**Supporting caution (LIKELY, high design weight):**
S1. LLM assistance during requirements inspection *reduced* smell-detection accuracy with no time saving, and learning with LLM support from the start slowed skill acquisition (https://arxiv.org/abs/2608.21298, snippet). The sanitizer must therefore be a *selective* interrupter (stakes-gated, §4 P2), never an always-on co-inspector — always-on is the measured-harm configuration.

## 4. Design Principles for T-009 (encode these in the fold)

**P1. Three heuristics, one triage output. [sanitizer core]**
H1 *split check*: does this turn contain two separable deliverables/goals presented as one (conjunction of unrelated verbs, two success criteria, "and also")? H2 *XY-probe*: is the stated request Y a conjectured solution to an unstated X (tool/implementation named before the goal; "how do I X…" where X presupposes the approach)? H3 *clarify-vs-absorb*: stakes-gated decision — clarify only when downstream cost of guessing exceeds interruption cost (stakes test, T-006 remainder owns the criterion). Output is always triage: SPLIT (two rows) / PROBE (one question naming the suspected X) / ABSORB (proceed, log the assumption).

**P2. Selective by construction; always-on is the measured-harm configuration. [S1 + F1]**
CLAM corroborates selectivity (F1); the inspection study measures harm from always-on assistance (S1). The sanitizer fires on H1/H2 signals *and* stakes, never on signal alone. Low-stakes conflation absorbs with a logged assumption; high-stakes conflation clarifies with a ConRAP-shaped question (F5).

**P3. Tune for task splits, not pronoun splits. [F6 + T-037 boundary]**
Pronoun/reference ambiguity belongs to the T-037 rule; the sanitizer's recall budget goes to goal/task conflation (two deliverables, solution-masquerading-as-goal). A sanitizer evaluated on referential benchmarks is miscalibrated by construction.

**P4. Weight signals by downstream impact: pronouns/conflation first, style last. [F4]**
Bayesian evidence ranks ambiguous pronouns as strongly corrupting and passive voice as minor. The sanitizer never blocks on style flags (passive, weak modal) — those are ledger notes at most.

**P5. Fix shape is pattern-recommendation, clarify shape is missing-slot question. [G1 P4 + F5]**
Fold inherits the G1 P4 decision: sanitizer output follows Paska's proven flag-to-pattern template; clarification questions name the missing slot via the global-difference trick (what sibling requests carry that this one lacks).
