# RESEARCH_BASIS.md — why each mechanism exists

**One row per mechanism.** A mechanism is a rule, gate, or check the protocol actually enforces. Each row states the claim it makes, the research it rests on with an effect size where one exists, the software-engineering practice it maps to, and the falsifier that would show the claim is wrong.

**Rule (load-bearing, so it sits here at the top):** a mechanism with no source is deleted, not padded. One row per mechanism; a citation that only decorates an explanation does not get a row. Full literature lives in `docs/research/` (`INDEX.md` lists it) with the inline anchors in the step files.

**Scope.** Mechanisms the protocol enforces — a rule, gate, or check in `steps/` or `docs/` that changes behaviour.

**Counterexample.** An evidence note inside an explanatory paragraph does not need a row. The column exists for mechanisms, not for prose.

**Check.** Lint R11c — at least eight rows, every row carrying five non-empty cells (mechanism, claim, basis, practice, falsifier), and this file linked from `docs/PROTOCOL_MODEL.md`. A row may not assert a claim with no source and no falsifier.
